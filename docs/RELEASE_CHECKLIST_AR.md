# قائمة مراجعة GitHub قبل النشر العام

## الملفات والمحتوى

- [ ] تأكد من أن الأرقام في README تطابق أحدث صورة معتمدة ونفس `Filter Context`.
- [ ] طابق أسماء صفحات Power BI السبع مع التبويبات الفعلية، وأضف صورها بعد تنقيح المعلومات الشخصية.
- [ ] راجع أسماء الملفات والمسارات ومراجع Markdown بعد الرفع.
- [ ] نفّذ فقط استعلامات `sql/read_only` في بيئة مخولة للتحقق من الأعمدة والنتائج، ووثق تاريخ التحقق.
- [ ] احتفظ بأصل `BikeStores_Business_Analysis_01.sql` داخل نسخة محلية خاصة، وليس المستودع العام.
- [ ] لا تنشر ملفات Lab الخاصة بـBackup/Restore/Permissions أو أي ملفات بأسماء شخصية قبل المراجعة.

## الأمن والخصوصية

- [ ] تأكد من عدم وجود كلمات مرور أو Tokens أو بريد شخصي أو مسارات محلية حساسة.
- [ ] لا تنشر ملفات `.bak` أو `.mdf` أو `.ldf` أو بيانات عملاء غير مصرح بها.
- [ ] راجع ملف PBIX قبل إضافته؛ هو مستبعد افتراضيًا بواسطة `.gitignore`.
- [ ] راجع رخصة أو شروط استخدام بيانات BikeStores قبل النشر العام.
- [ ] اختبر عرض Mermaid والجداول وروابط الملفات داخل README.

## شروط عدم المبالغة في الادعاءات

- [ ] لا تصف الحزمة بأنها Production-Ready أو قابلة لإعادة الإنشاء تلقائيًا قبل اختبار مستقل.
- [ ] لا تصف DW Refresh بأنه Incremental؛ الموجود في المصدر Full Refresh مع Incremental Lab منفصل.
- [ ] لا تعلن أن Power BI Scheduled Refresh يعمل؛ إعداد Gateway مؤجل.
- [ ] لا تضف رابط تقرير Power BI عامًا إلا بعد التأكد من صلاحيات مشاركة مناسبة.

## طريقة النشر

1. أنشئ Repository جديدًا على GitHub وحدد **Private** مبدئيًا.
2. ارفع محتويات هذا المجلد بعد مراجعتها، مع الاحتفاظ ببنية المسارات.
3. افتح README داخل GitHub وتحقق من الرسومات والروابط.
4. أضف الصور المصرح بها ووثق أسماء الصفحات السبع.
5. عند اكتمال المراجعة، يمكنك تغيير Visibility إلى Public إذا كانت لديك حقوق مشاركة المحتوى.
